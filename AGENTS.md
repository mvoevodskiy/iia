# Восстановление open-core

Рабочая основа — новое открытое ядро. Старое ядро master/vendor — эталон
пользовательской логики и визуального поведения Telegram, а не код для
механического переноса или возврата в runtime.

Воспроизводить прежние сценарии: действия, переходы меню, состояния, тексты,
анимации, ошибки, остановку и завершение ответа. Переносить логику, адаптируя
реализацию к архитектуре нового ядра. Разделять код на модули и подмодули по
ответственности; использовать существующие обработчики вместо параллельных
реализаций одного действия. Поддержку Claude/Anthropic и Codex сохранять.

Перед исправлением читать нужный референс; после проверять поведение и связи
модулей тестами. Не обещать полную эквивалентность старому ядру по одному тесту.
Сохранять привычный интерфейс; менять его лишь в явно запрошенной доработке.
Не заменять работающий сценарий заглушкой или фиктивным индикатором.

Этапы сохранять отдельными локальными коммитами: правила/контракт, изменение
поведения с проверками, выкладка/приёмка. В описании фиксировать изменённые
связи модулей, результаты и откат. Не смешивать посторонние изменения и
не переносить прежние коммиты целиком без оценки. Не push без поручения.

Текущая цель владельца: одна canonical source/release база, маршрутная навигация
по коду и разделение крупных смешанных файлов без изменения прежнего UI/поведения.
Canonical-ветка — codex/open-core-reference-tests. Разрешены реализация и проверки
этой цели; согласованная выкладка на JAR1 и Telegram-проверки сохраняют прежние
границы: не менять auth/ключи/workspace/model/effort/session, SSH/firewall и OS.

Начинать поиск с [docs/CODEMAP.md](docs/CODEMAP.md): задача → модуль → функция → тест.
После переноса обновлять прямые/обратные ссылки. Не создавать отдельную реализацию
для каждой установки: [shared profile](.msb/bot/shared/README.md) задаёт msb/jar1,
профиль jar1 сохраняет .iia и прежний OS engine UI. Персональные данные не входят в Git.

[Release pipeline](tools/release/README.md) берёт runtime, тесты и инструменты из
одного commit. Не накладывать ad-hoc source patches после экспорта. Откат — code-only
backup текущего release; vendor остаётся behavioral reference. Не запускать
bootstrap/OS-миграцию в рамках этой цели. Не объявлять релиз выложенным или принятым
по локальному PASS: финальный source commit, проверка артефакта, startup и живая
Telegram-приёмка фиксируются раздельно.

Операторские инструкции и отчёты: соседний репозиторий AgentsMania/deployment/ops/jar1/.
Не включать секреты, приватные архивы, node_modules и установленный runtime в Git.
